### `현재/`

- **`도적-트스/compare.html`** — **메인 작업물.** 도적 표창(트스/럭세) 환산 + 데미지 + 비교/가성비 계산기.
  - 환산/비교/아이템관리 3탭. 잠재·버프·스킬·부스탯 cycle·크리(합연산)·LS/TT 특수공식.
  - 가성비 효율(%/억) + 트스 스킬북 기대비용, 레벨연동, 부스탯 최적화 버튼, 아이템 복사 등.
  - `도적-트스/README.md` — 공식/출처/UI/TODO 상세. `참고/` `자막/` 에 검증 출처 자료.

## 알려진 차이

### 크리 데미지 공식 — 곱연산 → 합연산 [해결됨, 2026-05-28]

옛메 / 메플플의 크리티컬은 **합연산** 임 (곱연산 아님). 즉 1타 데미지가 ×2 배 되는 게 아니라, 스킬%p 에 크리 추가%p 가 더해지는 구조.

기존 코드 (틀림): `crit = perHit × (1 + perCrit/100)`
수정 (맞음): `crit = stat × (skillDmg + perCrit) / 100`

| 조건 | 크리 추가 %p |
|---|---|
| 크리스로우 30 (만렙) | +100 |
| 쓸샾 (10/15 spec) | +115 (= 100 활성 + 15 크댐) |
| 만샾 30 (15/40 spec) | +140 (= 100 + 40) |

검증 (관측 데이터, WDEF 차감 + 총뎀 9% 후):
- 옛 spec, WDEF 800 (스켈레곤), 샤프X → 계산 24,831 vs 관측 24,815 (+16) ✓
- 옛 spec, WDEF 235, 샤프X → 25,509 vs 25,436 (+73) ✓
- 새 spec, WDEF 235, 쓸샾 → 34,827 vs 34,607 (+220) ✓
- 새 spec, WDEF 235, 샤프X → 22,871 vs ~22,000 (표본 노이즈) ✓

출처:
- [arca 옛메 크리 계산방식](https://arca.live/b/mapleland/114593305) — "옛메의 크리티컬은 기본적으로 곱연산이 아니라 합연산이다"
- 메플플 마갤 "(허밋기준)잠재 크확의 효율에 대해" — "크리티컬 데미지 계산은 최종데미지에 곱연산되는게 아니라 스킬의 1타수 퍼뎀에 크리티컬 데미지만큼 합연산"

수정 위치: [compare.html:1248-1252](현재/도적-트스/compare.html:1248) — `perHitCritMax/Min = statMax/Min × (skillDmgPct + perCrit) / 100`

### 스공 (도적 트스 환산기) — STR 누락 [해결됨, 2026-05-28]

표창 도적 부스탯 공식은 `LUK × 3.6 + (STR + DEX)` (기존/README.md L74 무기상수표) 인데, 환산기가 DEX 만 더하고 STR 을 빼먹어서 인게임 대비 `STR × WA / 100` 만큼 stat 이 낮게 나왔음.

해결: `현재/도적-트스/compare.html` 캐릭터 입력에 **표기 STR** 칸 추가 (인게임 캐릭터창 STR 값 그대로 입력). 신규 공식: `floor((LUK × 3.6 + DEX + STR) × WA / 100)`.

검증 (LUK 1434 / DEX 141 / WA 150 / 표기 STR 12):
- 표창 + 혼테일: 계산기 7,973 = 인게임 7,973 ✓
- 표창 X + 혼테일: 계산기 6,644 = 인게임 6,644 ✓
- 표창 + 혼테일 X: 계산기 6,378 = 인게임 6,378 ✓

사용자 STR 12 의 출처: 기본 4 + 모자 +6 + 훈장 +2 = 12 (allstat% 8% 까지 적용 후 floor). 환산기는 base STR 컬럼을 따로 두지 않고 인게임 표시값을 그대로 받음 — 사용자 의도 (`힘 입력칸 따로 적게 하자 표기 수치`).

### 데미지 min/max 는 균등분포 (정규분포 아님) [2026-05-30]

구 메이플 클라이언트가 선형 난수로 `min + (max-min)×rand` 계산 → min~max 구간 **균등(uniform)**. 종 모양 정규분포 아님.
- 기댓값 `(min+max)/2` 는 균등분포 평균과 일치 → 환산기 기댓값 계산 OK.
- "거의 max 로 뜬다"는 오해 — 범위 전체에 골고루. 표본 적으면 실제 min/max 에 잘 안 닿음.
- 크리 섞이면 이봉형(bimodal).
- ⚠️ 표준 모델 기준 (레포 측정값 아님, 참고 자료는 기댓값만 다룸). 상세: [도적-트스 README §4.9](현재/도적-트스/README.md).

### 메용(메이플 용사) boost — 기어%로 뻥튀기되던 버그 [해결됨, 2026-05-30]

메용 boost 를 base 에 더한 뒤 기어 스탯% 를 곱해서 (`(base + boost + 깡) × (1 + 기어%)`) 기어% 만큼 과대 적용됐음.
- DEX 는 기어% 가 작아(~10%) 안 틀렸지만, LUK 은 기어% 가 커서(117%) 크게 어긋남 → "메용 켜면 LUK 만 안 맞음" 증상.

올바름: 메용 boost 는 **순수 base AP 기준 flat, 기어% 곱셈 '밖'에서 합산**.
```
메용% = ceil(메용Lv / 2)   (Lv10=5%, Lv20=10%, Lv30=15%)
Total = floor((base + 깡) × (1 + 기어%/100)) + floor(base × 메용%/100)
```

검증 (도적 lv135, 순수 LUK 633 / DEX 74, 기어 LUK% 117 / DEX% 10):
- 메용 OFF: 1614 / 177 (변화 없음)
- 메용 10 (5%): LUK **1645** / DEX **180** = 인게임 ✓ (수정 전 1681 로 +36 오버)

부스탯 cycle(요구 DEX 판정)도 동일하게 메용 flat 을 기어% 밖에서 더하도록 수정.
수정 위치: `현재/도적-트스/compare.html` `computeStats` + `simulateCycle`.

### 디버깅 팁 — "Save Page As" HTML 의 input 값

저장된 HTML 의 `<input value="...">` 는 **초기 속성값**만 보존됨. 사용자가 타이핑한 `.value`(실제값)는 저장 안 되고, 계산 결과(`r-luk` 등)에만 반영됨.
- 예: 저장본 base-luk `value="578"` 이지만 r-luk 1614 는 실제 base 633 으로 계산된 것.
- → 저장 HTML 디버깅 시 input value 속성 믿지 말고 **렌더된 결과값(r-*)으로 역산**할 것.

### 쓸샾 장갑 활성 임계 — 계산기가 더 빡셈 [미해결]

쓸샾 장갑(요구 DEX 160) 이 인게임은 순수 DEX **74** 면 켜지는데 계산기는 **82** 필요라고 함 (8 차이).
- 쟁점: 글로브 자체 DEX(15) 가 **자기 요구치**에 포함되는지(self-stat).
- 계산기 `simulateCycle` 은 "자기 자신은 자기 활성에 기여 못 함"(self 제외) 모델 → 인게임이 self 포함이면 임계가 더 낮아짐.
- 검증/수정 미완. (메용과는 별개 이슈)
